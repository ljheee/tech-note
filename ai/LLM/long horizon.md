# LLM 长程任务探索能力：结构化总结

> 日期：2026-08-17
> 来源：围绕 LLM context、注意力优化、预训练数据、RL 后训练、策略能力突破的递进式技术讨论

---

## 1. 长流程复杂推理任务的挑战

### 1.1 任务特征

长流程复杂推理任务（多步探索、中途纠偏、跨步骤决策）对模型的要求，与互联网文本训练出的能力存在系统性错配。挑战来自四个层面：

| 层面 | 挑战 | 具体表现 |
|------|------|----------|
| 数据分布 | 长程依赖数据稀缺 | 互联网文本以短程结构为主（段内指代、几句间逻辑），超长程互相依赖的内容稀少；拼接长序列反而教出"远处内容无关"，引发 context distraction |
| 知识形态 | 策略性知识缺失 | 文本记录"结果"不记录"过程"——专家"尝试→失败→换向→再试"的探索过程几乎从不被记录，模型学到的是"问题→答案"的陈述性映射，而非"面对未知如何决策"的程序性策略 |
| 训练信号 | credit assignment 极难 | 几百步决策共享一个稀疏终局信号，"第 47 步方向选错"这类归因统计上极低效；轨迹越长问题越尖锐 |
| 运行时支撑 | 有效上下文受限 | 标称窗口 ≠ 有效窗口（lost in the middle，中部信息检索率显著下降）；探索是串行有状态的，失败历史必须留在模型视野内才能成为后续决策输入 |

### 1.2 典型失败模式

模型面对这类任务的典型表现是"一条路走到黑"：在错误方向上做很充分的推理而不回头，或者对历史有完美记忆却抽取不出决策规律——记住了"刚才 A 方法失败"，下一步照样重复 A。本质是：长链推理的"形态"可以具备，但"何时止损、往哪换向"的策略没有被训练出来。

## 2. 当前 LLM 能力边界的核心矛盾

### 2.1 核心矛盾陈述

**模型拥有充足的基础性知识（陈述性知识），但缺乏长程依赖、多轮决策推理所需的策略性/认知性知识（如何尝试解决问题的方法论）。** 两者是正交的层：

- 陈述性知识：给定问题 X，正确答案是 Y——来自预训练的统计学习，已足够丰富。
- 策略性知识：面对未知问题，先试什么、怎么判断方向、何时回头——需从"实际尝试 + 反馈信号"中学出，预训练的数据分布里几乎不存在。

### 2.2 矛盾的根源：互联网数据只记录结果，不记录过程

论文呈现最终方案、教程呈现正确路径、代码仓库呈现调试完的代码。探索过程的不可见，使监督学习范式（无论预训练还是 SFT）天然补不上这一层。这不是数据量问题，是数据分布的结构性偏差——堆再多的互联网文本也改变不了"过程不被记录"这个事实。

### 2.3 相关的次级矛盾

- **能力 vs 载体**：context 长度是探索能力的载体（工作台大小），不是来源（会不会用工作台）。给模型一本容量无限的笔记本，解决的是"不忘"，不解决"会想"。反证：AlphaGo 的策略在极小局面表示上学出，不依赖长窗口。
- **标称 vs 有效**：窗口装得下 ≠ 用得好。有效上下文靠数据配方和训练 recipe，不靠算力。
- **RL 的重加权争议**：pass@k 研究提示 RLVR 可能主要是把基础模型已有能力重新加权变稳定，而非无中生有新能力——若探索策略的种子在预训练分布里不存在，后训练 RL 可能放大不出它（尚有争议，无定论）。

## 3. 突破长程任务的关键

### 3.1 核心公式

**策略突破 = RL 类训练（来源）× 长上下文（载体）× 推理时搜索（放大器）**

三者是乘法关系，任一为零则乘积为零。单押 context 加长或单押算力，是当前对 LLM 进展最常见的两类误读。

### 3.2 RL 如何绕开数据墙

RL 不需要预存的长程依赖数据——轨迹在环境交互中自造：一条完整轨迹里"第 3 步决策"与"第 300 步结果"存在真实因果依赖，正是教科书定义的长程依赖数据。数据墙被"造数据"绕开，但墙移到了别处：

- **credit assignment**：稀疏终局奖励 → 用过程奖励、GAE/折扣因子、课程学习、hindsight relabeling 加密度。
- **奖励信号质量**：语言任务"做对了"难自动判定（见第 4 章）。

### 3.3 数据生产链：RL 发电，SFT 输电

| 环节 | 角色 | 理由 |
|------|------|------|
| RL（头部实验室，大规模模型） | 策略数据发生器 | 极贵且不稳定，但产出含试错/回头/自我验证的高质量探索轨迹，是竞争壁垒 |
| SFT 蒸馏（生态玩家） | 策略数据传播器 | 便宜、稳定、离线可复用；R1 的 80 万条轨迹 SFT 到 Qwen/Llama（R1-distill）超过多数直接 RL 方案 |
| DPO 类离线方法 | 廉价对齐通道 | RLHF 目标的近似闭式解，退化为离线监督学习，无 rollout 无奖励模型 |

RL 贵的四个来源：rollout 开销（样本成本高于 SFT 一到两个数量级 × 组内多条采样）、多模型驻留（PPO 需 4 个模型）、生成-评估-训练实时流水线的系统复杂度、on-policy 数据不可复用。不稳定的三种模式：reward hacking、熵崩溃（探索性死亡）、格式漂移。GRPO 砍价值网络、组内相对比较，是工程折中。

### 3.4 注意力与上下文的工程基础（作为支撑条件）

- 无损优化已普及：FlashAttention（O(n²) 显存→O(n)）、GQA、PagedAttention——属于"免费午餐"。
- 有损优化（稀疏/线性注意力/SSM/混合架构）与精确检索做交易，混合架构为主流方向。
- 长上下文训练需分阶段扩展 + RoPE 缩放（NTK/YaRN）；算力定"能不能"，数据工程与 recipe 定"好不好用"。
- 长程探索的兑现最终取决于按任务可验证程度排序的渐进征服（见第 4 章）。

## 4. 奖励可验证的长程任务 vs 开放域的长程任务

### 4.1 两类任务的分野

| 维度 | 可验证域 | 开放域 |
|------|----------|--------|
| 典型任务 | 数学、代码、带测试的工具调用 | 架构决策、线上故障诊断、技术方案 |
| 奖励信号 | 程序化判定（答案对错、测试通过） | 无程序化"做对了"判定 |
| 环境 | 沙箱/模拟器现成 | 无高保真模拟器，真实试错成本是业务事故而非卡时 |
| RL 突破可能性 | 高，正在发生（o1/o3、R1） | 低，短期难 |
| 卡点 | 主要是成本，算力可摊薄 | 奖励不可验证 + 环境不可模拟 |

### 4.2 不计成本跑 RL 的边界

算力能买到的是**采样宽度兑换策略质量**（best-of-n 筛选、GRPO 组内比较；o3 在 ARC-AGI 的路线）。买不到的三堵墙：①奖励可验证性——开放任务的信号源本身是难题；②高保真环境——工程问题而非算力问题；③能力边界是否真被扩展——RL 重加权争议（见 2.3）。

### 4.3 可验证域能力向开放域的迁移：分层结构

| 可验证域学到的 | 迁移强度 | 机制 |
|----------------|----------|------|
| 长链推理"形态"（探索→质疑→验证→回退） | 强迁移 | 蒸馏 SFT 即可跨域扩散，已被反复验证（R1 蒸馏数据提升写作/通识推理） |
| 元策略（先建假设、验证再深入、不确定时分支） | 中等 | 作为跨域认知习惯泛化，深度有限 |
| 领域策略（代码调试套路、数学构造技巧） | 基本不迁移 | 领域绑定；写方案的 trade-off 权衡是另一套策略 |
| Agent/工具使用技能 | 几乎不迁移 | 绑死具体环境与工具，且可能倒挂（reasoning tax） |

**注意负迁移**：reasoning tax——重 RL 优化可验证域后，指令跟随、创意写作等能力可能退化。迁移不是白拿的。

### 4.4 开放域的三条绕墙路线

1. **任务可验证化工程**：把开放任务改造成可验证形态（方案→rubric 自动评分；诊断→对照历史根因库判定）。
2. **LLM-as-judge / 生成式奖励模型**：强模型当裁判，但裁判本身成为新的 reward hacking 目标——模型学会说服裁判而非做对事。
3. **过程奖励替代结果奖励**：不判终局对错，判每步是否合理。

三条都在推进，无一被证明彻底打通。**总体判断：可验证域 RL 是孵化器，解决"会不会探索"的元问题；每个开放域的具体策略仍须在域内拿到信号才能练出。迁移解决元问题，解决不了"在这个领域往哪探索"的具体问题。**

## 5. 模型突破之前，agent 框架层的工程方法

### 5.1 定位：策略的工程化过渡形态

在模型内化的长程策略成熟之前，agent 框架的本质是**把 credit assignment 从模型参数挪到工程代码**——用人类写死的规则替模型做"哪步重要、何时回头"的判断。代价是泛化性差（每类任务需人工设计流程），收益是当天可用。模型侧的进步会降低框架复杂度，但不会消解"如何系统探索未知问题"这个问题本身——框架层的探索方法论工程化具有独立价值。

### 5.2 框架层方法谱系

| 方法 | 弥补的模型短板 | 实现形式 |
|------|----------------|----------|
| 任务分解 | 长程规划能力缺失 | 多阶段流水线、子 Agent 分工 |
| 策显式注入 | 策略知识缺失 | 三层 Prompt（元策略 + 领域知识 + 工具手册），把人类专家隐性策略（先查什么、怎么验证假设、何时收窄）显式编码 |
| 深度检查门 | "一条路走到黑"、浅层分析 | 强制多步探索的门槛校验（如工具调用数、证据完整性检查） |
| 子 Agent 并发 | 单轨迹决策质量低 | 并行多方向探索，模拟"尝试多个方向"，等价于工程层的 best-of-n |
| 止损/重试规则 | 不会判断何时回头 | 失败重试上限、会话恢复、退避策略 |
| 上下文组装管理 | 长上下文下"装得下用不好" | 截断/压缩/RAG 注入的组装策略；控制注入体量（中文与 JSON 的 token 密度高） |

### 5.3 实例映射：alarm-craftsmen

告警深度排查工具是上述框架的典型落地：三层 Prompt 架构弥补策略知识缺口；深度检查门防止浅层分析（"看不出/可能是"类模糊结论被卡控）；子 Agent 并发调度模拟多方向探索；三次重试 + 会话恢复机制承担止损与容错。它在"模型策略成熟前"的窗口期内，用工程手段固化了人类排查专家的方法论。

### 5.4 框架层的演进方向

- **可验证化反哺训练**：框架运行中沉淀的"探索轨迹 + 最终根因"，若能对照历史根因库构造判定信号，可成为 RLVR 范式的训练素材——框架从"替代模型策略"逐步转为"为模型策略生产数据"。
- **规则逐步迁回参数**：随模型策略能力增强（可验证域 RL → 蒸馏扩散），框架中人为设计的检查门、分解规则会逐步简化，最终保留的是领域绑定和环境适配层——恰好对应迁移定律中"领域策略须逐域重挣"的部分。
- **两层长期共存**：模型解决"会不会探索"的元问题，框架持续解决"领域内怎么探索 + 环境怎么接"的具体问题——与第 4 章迁移分层结构一一对应。
