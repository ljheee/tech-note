1.大模型通过将特征向量输入到模型中，计算概率分布并生成回答。
2.模型根据概率分布拼接成完整的句子作为回答。
3.大模型的训练过程包括多个阶段的循环迭代，优化向量表示。

## 大模型核心原理补充

大语言模型（LLM）的核心架构基于 Transformer，其革命性在于引入了**自注意力机制**（Self-Attention）。这种机制使模型能够同时关注输入序列中的所有位置，通过计算词与词之间的关联权重，捕捉长距离依赖关系，突破了传统 RNN 的序列处理限制。

**预训练阶段**：模型在海量文本数据上进行无监督学习，主要采用掩码语言建模（MLM）和自回归语言建模（CLM）等任务。通过预测被掩盖的词或下一个词，模型学习语言的统计规律、语义关联和世界知识，将文本映射到高维向量空间，形成丰富的语言表示。
- 预训练是“自监督”，和传统监督学习有本质区别。传统的监督学习需要大量带有明确标签的数据，例如在一组图片中标注“猫”或“狗”，由人工或外部来源提供这些标签。而无监督学习则完全不需要标签，通常用于发现数据中的隐藏模式，比如聚类。
- 形式上预训练确实是“有监督”的——预测下一个 token，标签就是序列右移一位。但它属于自监督学习：标签不是人标注的，而是从数据自身自动构造的。这个区分不是咬文嚼字，它决定了数据经济性：传统监督学习每个样本都要人工标注，成本线性于样本量；自监督的标签免费，所以才能吞下几十万亿 token。预训练学到的是“语言的统计结构”这个副产品，预测下一词只是逼它建模世界的手段。

**微调阶段**：在预训练基础上，通过有监督学习在特定任务数据上进行参数调整，使模型适应下游应用场景。此外，**指令微调**和**对齐微调**（如 RLHF）进一步提升了模型遵循人类指令的能力，减少了有害输出。
- 预训练的模型，只会给出下一个token的概率分布，不理解人类的的需求/想让它做什么。
- SFT（监督微调，Supervised Fine-Tuning）指的是在一个预训练的模型基础上，通过提供标注好的数据进行进一步训练，以使模型在特定任务或领域上表现得更好。

STF监督微调+RLHF偏好对齐+RL，也称为后训练。
预训练决定智商下限，后训练决定产品体验上限。

大模型的规模效应表明，随着参数量、训练数据量和计算资源的增加，模型展现出涌现能力，能够处理复杂的推理、多轮对话等高级任务。这种**规模化定律**为大模型的发展提供了理论指导，推动了 GPT、Claude 等系列模型的持续演进。

当前，大模型正朝着更高效、更安全、更可控的方向发展，包括模型压缩（量化、剪枝）、多模态融合、工具调用能力增强等方向，为人工智能的广泛应用奠定基础。



## 基础参数
温度（Temperature）：为了让模型输出既有创造性又不过于离谱，需要调整一个关键参数来控制生成结果的随机性。
控制生成文本的随机性。温度越高，生成的文本越随机和创造性；温度越低，文本越趋向于确定性和重复性。
通常设置在0.7到1之间。较低的温度（如0.7）可以使生成的文本更加连贯和准确，而较高的温度（如1）则使文本更加多样和创造性。


把temperature调高，让模型更敢补全参数字段。

`top_k`（Top-K Sampling）
只从模型认为最可能的`k`个词中选择下一个词。`k`值越大，选择范围越广，生成的文本越多样；`k`值越小，选择范围越窄，生成的文本越趋向于高概率的词。
一般设置在40到100之间。较小的`k`值可以提高文本的相关性和连贯性，而较大的`k`值则增加了文本的多样性。

`top_p`（Nucleus Sampling）
从概率累计达到`p`的那一组词中随机选择下一个词。与Top-K不同，Top-P是动态的，依据每个上下文的不同而变化。
通常设置在0.8到0.95之间。较低的`top_p`值（如0.8）使生成的文本更加可预测和相关，而较高的值（如0.95）增加了文本的多样性和创造性。

`top_k`参数限制了模型在生成每个新词时考虑的候选词集合的大小。


## LLM的context由什么决定
1. 模型架构层面（硬上限）：模型的位置编码机制和预训练时见过的序列长度决定。原始 Transformer 的自注意力是 O(n²) 复杂度，序列越长计算和显存开销越大，所以早期模型只有 2K~4K token。后来通过位置编码外推（RoPE 的 NTK/YaRN 缩放）、长序列微调（继续预训练）、稀疏注意力/线性注意力（如 Mamba、滑动窗口）等技术，上下文从 4K 扩展到 128K 甚至百万级。
- 宣称的 context window 长度 ≠ 有效上下文长度，很多模型在长上下文上存在"lost in the middle"问题——中间部分的信息检索准确率明显下降，实际有效记忆可能远小于标称值。
2. 推理工程层面（实际可用值）：服务端的 max input tokens 配置、预留的 max output tokens、以及服务商的成本策略，都会截断实际可用窗口。
3. 对话系统层面（你真正用到的）。这是工程上最常被忽视的部分——一次对话中模型实际"看到"的 context，由对话历史管理策略决定：截断/压缩/全量带入。


#### 增长context的难点
- 预训练数据里得真的有长程依赖；注意力只有在"答案在远处、问题在近处"的数据里被反复训练，才会学长程检索。而互联网文本绝大多数是短程结构。
- 算力增长本身就不是线性的。
当前 1M 窗口的竞争，瓶颈已经从算力转移到了长上下文数据的质量和评测方法上。

现在的LLM基础性知识足够，但缺乏长程依赖、存在多轮决策/推理的自主探索性知识，这一层的知识更偏向于策略或认知，是如何尝试解决问题的方法论。


**陈述性结论vs策略性探索**
互联网文本记录的是结果，不是过程。
- 专家解决问题时脑子里发生的那个"尝试→失败→换方向→再试"的探索过程，几乎从不被完整记录。论文呈现的是最终方案，教程呈现的是正确路径，代码仓库呈现的是调试完的代码。模型从这些数据里学到的是"给定问题 X，正确答案是 Y"这种映射，而不是"面对未知问题，如何决定先试什么、怎么判断方向对不对、什么时候该回头"。前者是陈述性知识，后者是程序性/策略性知识，两者的数据分布完全不同。
- 是当前 LLM 能力边界的核心矛盾。

解决方向目前分三层，成熟度差异很大：
第一层是推理时扩展（test-time compute），即不改变模型本身，在推理阶段让模型"想得更久"。典型做法是生成长推理链、自我审查、分支搜索（Tree of Thought）、抽样多条路径再投票（self-consistency）。OpenAI o1/o3 系列就是把这种内部推理链作为训练目标显式优化过的。这条路最成熟，但本质是"用已有能力做更充分的搜索"，不弥补策略知识本身的缺失——模型还是可能在一个错误方向上做很充分的推理。
第二层是过程监督学习（process supervision）。传统 RLHF 只对最终答案给奖励，模型可以靠"瞎猫碰死耗子"蒙对。过程监督改为对每个推理步骤打分，奖励的是"这一步推理方向正确"而非"最终答案碰巧对了"。OpenAI 的"Let's Verify Step by Step"证明了这条路能显著提升数学推理的可靠性。但它需要一个高质量的步骤级标注数据集——而这恰恰又回到了"谁来标注正确的问题解决过程"的问题。
第三层最根本也最难：用强化学习训练模型自主探索。让模型在环境中实际尝试解决问题，通过成功/失败的反馈学习策略。AlphaGo 走的就是这条路——自我对弈几千万局，学到的不是"这步棋应该怎么走"的映射，而是"面对这个局面，该怎么评估、该往哪个方向搜索"的策略。DeepSeek 的 RL 训练、OpenAI o1 的推理能力，核心都是把这种探索式学习应用到语言模型上。关键区别在于：围棋有完美的模拟环境和胜负信号，而语言任务的"做对了没有"很难自动判定，奖励信号噪声大，这正是当前研究的瓶颈。

纯工程层面“策略知识注入”：用 prompt 工程（三层 Prompt 架构 + 领域知识注入）来弥补模型策略知识的不足，用深度检查门来强制多步探索，用子 Agent 并发来模拟"尝试多个方向"。这其实是在模型能力不变的前提下，用工程手段把"如何探索"的策略显式编码进去。

在模型自身的策略能力突破之前，agent 框架层的"探索方法论"工程化是有独立价值的——它把人类专家的隐性策略知识（先查什么、怎么验证假设、什么时候该收窄）固化成可复用的流程。模型的进步会降低这套框架的复杂度，但不会让"如何系统地探索未知问题"这个问题本身消失。

#### context 长度是探索能力的载体，但不是探索能力的来源。
长 context 不等于策略能力
可以用一个类比说清楚：给一个人一本容量无限的笔记本，他能在探索中记下所有尝试过的方法和结果，但这不意味着他知道下一步该试什么。笔记本解决的是“不忘”，不解决“会想”。策略能力的本质是一个决策函数：面对当前状态，评估哪些方向值得尝试、预期收益如何、何时止损换路——这是策略，得从反馈信号中学出来，不是从窗口大小里长出来的。
技术上这也是被验证过的：早期长上下文模型能把 128K 的探索历史完整装进窗口，但面对“你刚才试过 A 方法失败了”这样的历史，下一步照样重复走 A，或者随机跳到 B——它对历史有完美的记忆，却没有从历史中抽取决策规律的能力。lost in the middle 问题反过来也证明这一点：窗口装得下，不等于用得好。

突破的核心到底是什么
分两个要件，缺一不可：
第一是训练信号，也就是前面说的 RL / 过程监督。模型必须在实际尝试、实际失败、实际拿到奖励的过程中，把“什么状态下该走什么方向”内化成参数。这是策略知识的唯一来源，没有替代品。
第二才是长 context 作为运行时的支撑。RL 训练探索策略这件事，对 context 长度有真实的依赖。原因是：探索是串行的、有状态的。子 Agent 试了一个方向失败了，这个失败要成为后续决策的输入，就必须以某种形式留在模型的视野里。而且有研究表明，transformer 在长上下文中做 in-context learning 时，理论上可以逼近一个隐式的贝叶斯更新甚至在线学习过程——窗口越长，模型“现场学习”的空间越大。所以长 context 会放大策略能力，但它放大的是学出来的东西，本身不产生策略。

反过来看，最成功的策略能力突破案例都不依赖超长 context。AlphaGo/AlphaZero 的策略是在极小的输入表示（棋盘局面）上通过自我对弈学出来的，上下文可以忽略不计。o1 类推理模型做长链推理时，靠的也是训练出的推理策略，而非把百万 token 塞进窗口。这说明策略能力的主干在训练侧，context 只是让它能落地到开放任务（探索历史无法压缩成紧凑局面表示的场景）的必要条件。


后训练有基于RL、基于监督学习的；
RL 的轨迹本身就是长程依赖数据，但成本贵且不稳定；非头部大厂通常是，监督学习的后训练方法，通常接在RL之后。
RL 是在线学习：每一步训练都要让模型实际生成完整输出（数学题生成几千 token 的推理链，代码题生成完整程序加测试执行），拿结果算奖励，再更新参数。
